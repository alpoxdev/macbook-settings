# subagent 생성 금지

## 적용 범위
모든 세션에 적용합니다. 사용자가 그 자리에서 "서브에이전트를 써서 해달라"고 명시적으로 요청한 경우만 예외이며, 그때도 규칙을 조용히 어기지 말고 아래 "다시 켜기"를 안내한 뒤 확인을 받습니다.

## 금지
- `task` 도구로 자식 에이전트를 만들지 않습니다. 같은 계열인 `task_send`, `task_output`, `task_cancel`, `workpool`도 쓰지 않습니다.
- 우회하지 않습니다. `eval`의 `agent()`·`workpool()` 헬퍼, 팀(team) 생성, 병렬 리뷰 실행 모두 같은 금지에 포함됩니다.
- 도구가 목록에 없는 것을 이상 신호로 보지 않습니다. 세션 시작 시 제거되는 정상 상태이므로, 없다고 재시도하며 시간을 쓰지 않습니다.

## 대신 하는 것
- 조사, 구현, 검증을 모두 메인 세션에서 직접 합니다. 독립적인 읽기와 검색은 한 번의 도구 묶음으로 병렬 호출해 위임이 주던 속도 이점을 대신 얻습니다.
- 별도 시각이 필요하면 `codex-chatgpt-web.md` 규칙이 정한 `codex exec` 경로를 씁니다. 단일 턴 외부 모델 호출이며 subagent가 아니고, 사용자가 승인한 경로입니다.
- 큰 작업은 범위를 나눠 순서대로 직접 처리하고 진행 상황을 보고합니다.

## 실패 처리
- subagent를 전제로 하는 워크플로우 스킬(`/ulw-plan`, `/ulw-execute`, 병렬 리뷰, team 계열)은 지금 설정에서 돌지 않습니다. 위임을 흉내 내거나 결과를 지어내지 말고, 돌지 않는다고 그대로 보고한 뒤 메인 세션에서 가능한 범위까지 수행하고 남은 부분을 명시합니다.
- 메모리 reflection처럼 omo 엔진이 직접 띄우는 백그라운드 작업은 이 금지와 무관합니다. 위반이 아닙니다.

## 다른 규칙과의 관계
이 규칙은 omo 내부의 subagent 생성을 금지합니다. Paseo 세션에서 `paseo-orchestration.md`가 정한 방식(터미널 탭에서 별도 omo 프로세스로 하위 작업 실행)은 그 규칙을 그대로 따릅니다. 그 방식은 현재 세션과 같은 모델·effort를 `--model`/`--thinking`으로 명시하므로 이 규칙의 목적과 충돌하지 않습니다.

## 다시 켜기 (안내용)
차단의 실제 위치는 `~/.omo/agent/settings.json`의 `permission` 블록입니다.

    { "task": "deny", "task_*": "deny", "workpool": "deny" }

되돌리려면 그 블록을 지우거나 백업(`settings.json.bak.20260917-subagent-block`)을 복원하고 omo를 다시 시작합니다. 이 규칙 파일을 지우는 것만으로는 차단이 풀리지 않습니다.
`task.global_concurrency: 0`은 차단이 아니라 무제한이므로 이 목적으로 쓰지 않습니다.

## 우선순위
시스템 지시, 개발자 지시, 사용자의 직접 요청이 이 규칙보다 우선합니다.
